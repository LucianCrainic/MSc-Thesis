\section{Inference engines: running a trained model}
\label{sec:inference-engines}

A trained model supplies an architecture and learned weights; an
\textbf{inference engine} is the software that executes it to answer requests.
It loads the model, prepares input tokens, manages weights, KV caches and
temporary buffers, and calls numerical kernels on the available processors.
It also coordinates prefill, repeated decode steps, token selection and
stopping, returning generated text to the application.  In a serving system,
the engine can schedule and batch several requests.  It therefore connects
the application to the computation and memory operations described in the
previous section~\cite{llamacppproject2026,vllm2026}.

Two prominent, widely used open-source engines are \lcpp{} and vLLM.
\lcpp{} is a C/C++ implementation designed to run models across a broad range
of hardware, including CPUs and GPUs, with support for quantized weights and
both local execution and server interfaces~\cite{llamacppproject2026}.
vLLM is an inference and serving engine designed for high throughput; it
combines request batching with efficient KV-cache management and provides
interfaces for applications to submit requests and receive
outputs~\cite{vllm2026,kwon2023pagedattention}.
Both fulfil the same basic role: turning a trained model and an input request
into an executable generation process.

\figref{fig:inference-engine-role} separates the model files, the engine and
the hardware.  The model supplies the learned parameters; the engine controls
their execution; the hardware performs the calculations and stores the
tensors.  The following section introduces the machines on which that work runs.
